> **작성일**: 2026-05-07
> **작성자**: 신현민
> **버전**: v1.0

## 1. 프로젝트 목적

키오스크와 모바일 앱 환경에서 사용자가 직접 메뉴를 골라 주문·결제하는 백엔드 시스템을 설계·구현한다.
단순 CRUD를 넘어, **다중 인스턴스 환경의 동시성 제어**, **이벤트 기반 비동기 처리**, **데이터 정합성 보장**을 실제 코드와 문서로 증명하는 것이 핵심 목표다.

---

## 2. 배경 및 문제 정의

| 구분 | 내용 |
|------|------|
| 학습 배경 | 경력 3개월 백엔드 개발자 1명이 5일 안에 실무 수준 동시성 설계 경험 |
| 해결할 기술 문제 | 다수 사용자가 동시에 같은 한정 메뉴를 주문할 때 재고 정합성 보장 |
| 해결할 기술 문제 | 동일 사용자의 동시 주문/충전 시 포인트 잔액 무결성 보장 |
| 해결할 기술 문제 | 주문 트랜잭션과 외부 분석 플랫폼 전송의 결합도 분리 |
| 해결할 기술 문제 | 인기 메뉴 집계의 정확성과 응답 속도 동시 보장 |
| 비즈니스 목표 | 5일 안에 4개 핵심 API + 동시성 설계서·테스트 완성 |

## 3. 프로젝트 범위

### In Scope

- 회원 가입 / 로그인 / JWT 인증 (기존 SecurityConfig 재활용)
- 메뉴 목록 조회 (카테고리 단일 레벨)
- 포인트 충전 (Redis 분산락 기반 직렬화)
- 주문/결제 (포인트 차감 + 재고 차감, 비관적 락 기반)
- 인기 메뉴 조회 (최근 7일 Top 3)
- 포인트 이력 기록 (append-only)
- 주문 이벤트 비동기 발행 (Kafka, AFTER_COMMIT)
- 분석 플랫폼 전송 컨슈머 (Mock)
- 인기 메뉴 집계 컨슈머 (Redis ZSET)
- 인기 메뉴 캐시 정합성 보정 스케줄러
- 다중 인스턴스 환경 동시성 테스트
- Flyway 기반 시드 데이터 (일반/한정/재고극소 메뉴)

### Out of Scope

- 어드민 / 매장 직원 기능 (메뉴 등록·재고 입고 API 없음)
- 매장·지점 분리 (단일 매장 가정)
- 주문 후 상태 (제조·픽업·완료·취소·환불)
- 외부 PG 연동 결제 (포인트 전용)
- 요청 멱등성 보장 (idempotency-key)
- 프론트엔드

## 4. 기술 스택

| 계층 | 기술 | 선택 이유 |
|------|------|-----------|
| Language | Java 17 | LTS, Record 기반 DTO, Pattern matching |
| Framework | Spring Boot 3.x | 업계 표준, `@TransactionalEventListener` 내장 |
| ORM | Spring Data JPA + QueryDSL | 기본 CRUD는 JPA, 인기 메뉴 집계 등 동적 쿼리는 QueryDSL |
| DB | MySQL 8 | 비관적 락(`SELECT FOR UPDATE`), 트랜잭션 격리 수준 명시적 제어 |
| Cache / Lock | Redis (Redisson) | 분산락(포인트 충전), 인기 메뉴 ZSET 캐시 |
| Message Broker | Kafka | 주문 이벤트 비동기 전파, 컨슈머 그룹 분리 |
| 인증 | JWT (HS256) | 기존 SecurityConfig 재활용, 무상태 |
| Migration | Flyway | 스키마 버전 관리 + 시드 데이터 주입 |
| 컨테이너 | Docker + Docker Compose | MySQL/Redis/Kafka 로컬 환경 통합 |
| 테스트 | JUnit 5 + Testcontainers | 동시성 시나리오를 실제 인프라로 검증 |

## 6. 핵심 제약 사항

1. **5일 내 완료** — 도전 요구사항(다중 인스턴스/동시성/일관성/테스트) 우선
2. **경력 3개월 1인 개발** — Outbox 패턴 등 고난도 기법은 ADR에서 검토만 명시
3. **포인트 결제 전용** — 외부 결제 게이트웨이 없음, 가점유 모델 불필요
4. **단일 매장 가정** — 메뉴/재고가 매장별로 분기되지 않음
5. **다중 인스턴스 가정만, 실제 배포는 없음** — 코드/설계는 분산 환경에서 안전하되, 제출은 `docker-compose` 단일 환경
