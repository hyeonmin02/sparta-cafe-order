# 12. 에러코드 설계서

> **버전**: v1.0
> **연관 문서**: 06. API 명세서, 09. 동시성 제어 설계서

## 1. 에러 응답 표준 구조

```json
{
  "code": "P004",
  "message": "포인트 잔액이 부족합니다.",
  "details": {
    "required": 10000,
    "current": 7500,
    "shortage": 2500
  }
}
```

| 필드 | 타입 | 필수 | 설명 |
|------|------|------|------|
| code | String | ✅ | 도메인 prefix + 3자리 번호 (예: `P004`) |
| message | String | ✅ | 사용자/개발자가 이해할 수 있는 한국어 메시지 |
| details | Object | 선택 | 클라이언트 후속 처리에 필요한 부가 정보 |

---

## 2. 도메인 prefix 체계

| Prefix | 도메인 | 비고 |
|--------|--------|------|
| **A** | Auth (인증·토큰) | 로그인, JWT 검증 |
| **U** | User (회원) | 회원가입, 회원 정보 |
| **M** | Menu (메뉴·카테고리) | 메뉴 조회, 카테고리 |
| **S** | Stock (재고) | 재고 차감 |
| **P** | Point (포인트) | 충전, 차감, 이력 |
| **O** | Order (주문) | 주문/결제 |
| **L** | Lock (분산락) | Redisson, 비관적 락 타임아웃 |
| **G** | Global (공통) | 유효성, 알 수 없는 오류 |

> 도메인이 추가될 때 prefix 충돌이 없도록 한 글자(또는 두 글자) 규칙을 따른다. 향후 알림 도입 시 `N`, 채팅 도입 시 `CH` 등.

## 3. 에러코드 전체 목록

### 3-1. AUTH (A) — 인증·토큰

| code | HTTP | 메시지 | 발생 조건 |
|------|------|--------|-----------|
| A001 | 409 | 이미 사용 중인 아이디입니다. | 회원가입 시 loginId 중복 |
| A002 | 401 | 아이디 또는 비밀번호가 올바르지 않습니다. | 로그인 실패 |
| A003 | 401 | 인증이 필요합니다. | 토큰 부재 |
| A004 | 401 | 토큰이 만료되었습니다. | AT exp 경과 |
| A005 | 401 | 유효하지 않은 토큰입니다. | 서명 위조, 형식 오류 |

### 3-2. USER (U) — 회원

| code | HTTP | 메시지 | 발생 조건 |
|------|------|--------|-----------|
| U001 | 404 | 존재하지 않는 회원입니다. | userId 미존재 |

### 3-3. MENU (M) — 메뉴·카테고리

| code | HTTP | 메시지 | 발생 조건 |
|------|------|--------|-----------|
| M001 | 400 | 존재하지 않는 메뉴입니다. | menuId 미존재 |

| M003 | 404 | 존재하지 않는 카테고리입니다. | categoryId 미존재 |

### 3-4. STOCK (S) — 재고

|------|------|--------|-----------|---------|
| S001 | 422 | 재고가 부족한 메뉴가 있습니다. | stock.quantity < 요청 수량 | menuId, available |

### 3-5. POINT (P) — 포인트

| code | HTTP | 메시지 | 발생 조건 | details |
|------|------|--------|-----------|---------|
| P001 | 400 | 충전 금액이 올바르지 않습니다. | amount ≤ 0 | min |

| P003 | 422 | 포인트 잔액이 부족합니다. | balance < totalAmount | required, current, shortage |

### 3-6. ORDER (O) — 주문

| code | HTTP | 메시지 | 발생 조건 | details |
|------|------|--------|-----------|---------|
| O001 | 400 | 주문 항목이 비어있습니다. | items 배열 길이 0 | — |
| O002 | 404 | 존재하지 않는 주문입니다. | orderId 미존재 | orderId |

### 3-7. LOCK (L) — 분산락

| code | HTTP | 메시지 | 발생 조건 | details |
|------|------|--------|-----------|---------|
| L001 | 409 | 처리 중인 요청이 있습니다. 잠시 후 다시 시도해주세요. | Redisson tryLock 대기 타임아웃 | resource |
| L002 | 500 | 처리 중 중단되었습니다. | InterruptedException | — |

### 3-8. GLOBAL (G) — 공통

| code | HTTP | 메시지 | 발생 조건 |
|------|------|--------|-----------|
| G001 | 400 | 입력값이 올바르지 않습니다. | DTO 유효성 검증 실패 |
| G002 | 400 | 요청 형식이 올바르지 않습니다. | JSON 파싱 실패 |

| G006 | 503 | 일시적으로 서비스를 이용할 수 없습니다. | Redis + DB 동시 장애 |

## 4. HTTP 상태 코드 매핑 정책

| 코드 범위 | 의미 | 본 시스템 사용 |
|-----------|------|----------------|
| 400 | 클라이언트 입력 오류 | 유효성 위반, 존재하지 않는 리소스 참조 |
| 401 | 인증 실패 | 토큰 부재/만료/위조, 로그인 실패 |
| 403 | 권한 없음 | (확장 시 사용) |
| 404 | 리소스 미존재 | 회원, 카테고리, 주문 등 |
| 409 | 충돌 / 동시성 | 중복, 락 타임아웃 |
| 422 | 비즈니스 규칙 위반 | 잔액 부족, 재고 부족 |
| 500 | 서버 내부 오류 | 처리되지 않은 예외 |
| 503 | 외부 의존성 장애 | Redis + DB 동시 장애 |

### 422 vs 409 vs 400 구분

| HTTP | 본질 | 예시 |
|------|------|------|
| 400 | 형식이 틀림 | `amount: -1`, `items: []` |
| 409 | 다른 요청과의 충돌, 재시도 가능 | 락 타임아웃, loginId 중복 |
| 422 | 형식은 맞지만 비즈니스 상 처리 불가, 재시도해도 같은 결과 | 잔액 부족, 재고 부족 |

> **왜 잔액/재고 부족이 422인가?** 입력은 형식상 문제가 없고(400 아님), 충돌도 아니다(409 아님). 비즈니스 규칙 위반이며 같은 요청을 재시도해도 결과가 같다(현재 잔액/재고 상태 기준).

## 5. ErrorCode enum 구현

```java
package com.cafe.order.global.exception;

import lombok.Getter;
import lombok.RequiredArgsConstructor;
import org.springframework.http.HttpStatus;

@Getter
@RequiredArgsConstructor
public enum ErrorCode {

    // ===== AUTH (A) =====
    DUPLICATE_LOGIN_ID(HttpStatus.CONFLICT, "A001", "이미 사용 중인 아이디입니다."),
    INVALID_CREDENTIALS(HttpStatus.UNAUTHORIZED, "A002", "아이디 또는 비밀번호가 올바르지 않습니다."),
    UNAUTHORIZED(HttpStatus.UNAUTHORIZED, "A003", "인증이 필요합니다."),
    TOKEN_EXPIRED(HttpStatus.UNAUTHORIZED, "A004", "토큰이 만료되었습니다."),
    TOKEN_INVALID(HttpStatus.UNAUTHORIZED, "A005", "유효하지 않은 토큰입니다."),

    // ===== USER (U) =====
    USER_NOT_FOUND(HttpStatus.NOT_FOUND, "U001", "존재하지 않는 회원입니다."),

    // ===== MENU (M) =====
    MENU_NOT_FOUND(HttpStatus.BAD_REQUEST, "M001", "존재하지 않는 메뉴입니다."),
    MENU_NOT_AVAILABLE(HttpStatus.BAD_REQUEST, "M002", "판매 중지된 메뉴입니다."),
    CATEGORY_NOT_FOUND(HttpStatus.NOT_FOUND, "M003", "존재하지 않는 카테고리입니다."),

    // ===== STOCK (S) =====
    STOCK_INSUFFICIENT(HttpStatus.UNPROCESSABLE_ENTITY, "S001", "재고가 부족한 메뉴가 있습니다."),

    // ===== POINT (P) =====
    INVALID_AMOUNT(HttpStatus.BAD_REQUEST, "P001", "충전 금액이 올바르지 않습니다."),
    AMOUNT_LIMIT_EXCEEDED(HttpStatus.BAD_REQUEST, "P002", "충전 한도를 초과했습니다."),
    POINT_INSUFFICIENT(HttpStatus.UNPROCESSABLE_ENTITY, "P003", "포인트 잔액이 부족합니다."),

    // ===== ORDER (O) =====
    ORDER_ITEMS_EMPTY(HttpStatus.BAD_REQUEST, "O001", "주문 항목이 비어있습니다."),
    ORDER_NOT_FOUND(HttpStatus.NOT_FOUND, "O002", "존재하지 않는 주문입니다."),

    // ===== LOCK (L) =====
    LOCK_TIMEOUT(HttpStatus.CONFLICT, "L001", "처리 중인 요청이 있습니다. 잠시 후 다시 시도해주세요."),
    LOCK_INTERRUPTED(HttpStatus.INTERNAL_SERVER_ERROR, "L002", "처리 중 중단되었습니다."),

    // ===== GLOBAL/COMMON (G) =====
    INVALID_REQUEST(HttpStatus.BAD_REQUEST, "G001", "입력값이 올바르지 않습니다."),
    INVALID_FORMAT(HttpStatus.BAD_REQUEST, "G002", "요청 형식이 올바르지 않습니다."),
    NOT_FOUND(HttpStatus.NOT_FOUND, "G003", "요청한 리소스를 찾을 수 없습니다."),
    FORBIDDEN(HttpStatus.FORBIDDEN, "G004", "접근 권한이 없습니다."),
    INTERNAL_ERROR(HttpStatus.INTERNAL_SERVER_ERROR, "G005", "서버 오류가 발생했습니다."),
    SERVICE_UNAVAILABLE(HttpStatus.SERVICE_UNAVAILABLE, "G006", "일시적으로 서비스를 이용할 수 없습니다.");

    private final HttpStatus httpStatus;
    private final String code;
    private final String message;
}
```

## 6. BusinessException 설계

```java
package com.cafe.order.global.exception;

import lombok.Getter;
import java.util.Collections;
import java.util.Map;

@Getter
public class BusinessException extends RuntimeException {

    private final ErrorCode errorCode;
    private final Map<String, Object> details;

    public BusinessException(ErrorCode errorCode) {
        this(errorCode, Collections.emptyMap());
    }

    public BusinessException(ErrorCode errorCode, Map<String, Object> details) {
        super(errorCode.getMessage());
        this.errorCode = errorCode;
        this.details = details;
    }
}
```

**사용 예시**:

```java
// 단순 케이스
throw new BusinessException(ErrorCode.MENU_NOT_FOUND);

// details 포함
throw new BusinessException(
    ErrorCode.STOCK_INSUFFICIENT,
    Map.of("menuId", menuId, "available", stock.getQuantity())
);

throw new BusinessException(
    ErrorCode.POINT_INSUFFICIENT,
    Map.of(
        "required", totalAmount,
        "current", balance,
        "shortage", totalAmount - balance
    )
);
```

## 7. ErrorResponse DTO

```java
package com.cafe.order.global.response;

import java.util.Map;

public record ErrorResponse(
    String code,
    String message,
    Map<String, Object> details
) {
    public static ErrorResponse of(ErrorCode errorCode, Map<String, Object> details) {
        return new ErrorResponse(
            errorCode.getCode(),
            errorCode.getMessage(),
            details == null || details.isEmpty() ? null : details
        );
    }
}
```

> `details` 가 비어있으면 응답에서 제외하기 위해 `null` 처리. Jackson 직렬화 시 `@JsonInclude(NON_NULL)` 설정과 함께 사용.

## 8. GlobalExceptionHandler

```java
package com.cafe.order.global.exception;

import lombok.extern.slf4j.Slf4j;
import org.springframework.http.ResponseEntity;
import org.springframework.validation.FieldError;
import org.springframework.web.bind.MethodArgumentNotValidException;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.RestControllerAdvice;

import java.util.Map;
import java.util.stream.Collectors;

@Slf4j
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(BusinessException.class)
    public ResponseEntity<ErrorResponse> handleBusiness(BusinessException e) {
        ErrorCode ec = e.getErrorCode();
        return ResponseEntity
            .status(ec.getHttpStatus())
            .body(ErrorResponse.of(ec, e.getDetails()));
    }

    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ResponseEntity<ErrorResponse> handleValidation(MethodArgumentNotValidException e) {
        Map<String, Object> details = e.getBindingResult().getFieldErrors().stream()
            .collect(Collectors.toMap(
                FieldError::getField,
                err -> err.getDefaultMessage() != null ? err.getDefaultMessage() : "",
                (a, b) -> a
            ));
        return ResponseEntity
            .status(ErrorCode.INVALID_REQUEST.getHttpStatus())
            .body(ErrorResponse.of(ErrorCode.INVALID_REQUEST, details));
    }

    @ExceptionHandler(Exception.class)
    public ResponseEntity<ErrorResponse> handleUnexpected(Exception e) {
        log.error("Unexpected error", e);
        return ResponseEntity
            .status(ErrorCode.INTERNAL_ERROR.getHttpStatus())
            .body(ErrorResponse.of(ErrorCode.INTERNAL_ERROR, null));
    }
}
```

## 9. 클라이언트 처리 가이드

| code | 클라이언트 동작 권장 |
|------|----------------------|
| G001 INVALID_REQUEST | 폼 필드별 에러 표시 (details 활용) |
| A004 TOKEN_EXPIRED | 재로그인 유도 |
| M002 MENU_NOT_AVAILABLE | 메뉴 목록 새로고침 + 토스트 알림 |
| S001 STOCK_INSUFFICIENT | "메뉴 OOO 이 품절되었습니다" 안내 + 장바구니 갱신 |
| P003 POINT_INSUFFICIENT | "포인트가 부족합니다 (부족: 2,500P)" + 충전 화면 이동 |
| L001 LOCK_TIMEOUT | "잠시 후 다시 시도" 안내 (자동 재시도 X) |

> 본 시스템은 클라이언트 자동 재시도를 가정하지 않는다. 사용자의 명시적 의지로 재시도하도록 유도한다.

## 10. 로깅 정책

| 레벨 | 대상 |
|------|------|
| ERROR | 500, 503, 처리되지 않은 예외, Kafka 발행 실패 |
| WARN | 401 (잦은 토큰 만료/위조), 409 LOCK_TIMEOUT |
| INFO | 비즈니스 정상 흐름 (주문 생성, 충전 완료) |
| DEBUG | 422 (잔액 부족, 재고 부족) — 개발 환경만 |

> 4xx 비즈니스 에러는 INFO/DEBUG. WARN 이상은 운영 알람 대상이 될 수 있는 신호로 한정.

## 11. 추후 확장 시 고려사항

| 시점 | 추가 예상 prefix · code |
|------|------------------------|
| 주문 취소 도입 | O003 ORDER_NOT_CANCELABLE, O004 ORDER_ALREADY_CANCELED |
| 멱등성 도입 | G007 IDEMPOTENCY_KEY_REQUIRED, G008 IDEMPOTENCY_KEY_CONFLICT |
| 어드민 API | G004 사용 또는 새 prefix `AD` 도입 |
| 외부 PG 연동 | 새 prefix `PG` — PG001 PAYMENT_GATEWAY_TIMEOUT 등 |
| 알림 도입 | 새 prefix `N` |

> 본 문서는 현재 범위의 7개 API 에 한정된 에러만 정의. 도메인 확장 시 위 가이드를 따라 추가하며, 기존 코드 번호는 재사용하지 않는다 (역사 보존).
